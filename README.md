# Logistics Control

Система учёта грузовых перевозок на React/Vite и Node.js/Express. Backend поддерживает облачную базу Turso (libSQL/SQLite) и локальный SQLite-файл для разработки. В реестре хранятся маршрут, тип и вес груза, стоимость, диспетчер, водитель, статус и даты назначения и доставки. Отчёты показывают работу диспетчеров и водителей и выгружаются в Excel или PDF.

## Быстрый запуск

Требуется Node.js 22.12 или новее.

```bash
npm install
npm run seed
npm run dev
```

`npm run seed` полностью пересоздаёт локальную базу `backend/data/logistics.db`: удаляет старые записи, учётные записи и настройки и заполняет базу демонстрационными перевозками за последние два года. Команда добавляет 240 грузов, диспетчеров, водителей, типы груза и планы. Повторный запуск снова очищает базу и создаёт новый демонстрационный набор. Если выбрана облачная база, команда откажется стирать её; явный сброс демонстрационной облачной базы выполняется отдельной командой `npm run seed:cloud-reset`.

Демо-входы:

| Доступ | Email | Пароль |
|---|---|---|
| Администратор | `admin@demo.local` | `DemoPassword123!` |
| Наблюдатель | `observer@demo.local` | `DemoPassword123!` |

Для пустой базы без демонстрационных записей выполните `npm run seed:empty`. Команда также сбрасывает существующую локальную базу.

## Права доступа

- **Администратор** может добавлять сотрудников, менять их данные и роли, сбрасывать пароли и отключать или удалять доступ, а также управлять грузами, статусами, типами груза, архивом и планами.
- **Наблюдатель** может просматривать дашборд, реестр, сотрудников и отчёты. Запросы на изменение данных блокируются на сервере, даже если отправить их напрямую к API.

Управление находится в «Настройки → Учётные записи». В списке видны все профили, включая добавленные напрямую в базу и пока не имеющие входа. Создание аккаунта связывает его с таким профилем. После создания или сброса пароль показывается один раз; существующий пароль нельзя прочитать, потому что база хранит только его salted `scrypt`-хеш. При удалении аккаунта профиль и история перевозок остаются.

## Зарплата

Все цены, планы, зарплата, графики, уведомления и выгрузки показываются в долларах США. По умолчанию используется курс 1 USD = 87,45 KGS; администратор может изменить его во вкладке «Настройки → Расчёты». Старые значения сохраняются в базе в сомах, поэтому смена курса пересчитывает их только при отображении и вводе, не переписывая историю.

В разделе «Зарплата» начисления считаются по каждому грузу после доставки: диспетчеру начисляется 1,5%, водителю — 10% от стоимости заказа. Ставки можно менять в настройках расчётов. Отчёт поддерживает произвольный период до пяти лет и быстрые фильтры за текущий месяц и последние 30 дней. Сотрудник видит только собственные начисления, администратор — сводку и детализацию по команде.

## Перевозки и отчёты

Статусы груза: новый, назначен, в пути, доставлен, проблема и отменён. При смене диспетчера, водителя или статуса сохраняется история. В отчётах отображаются назначенный диспетчер и водитель доставки, маршрут, даты назначения, фактическая или плановая дата доставки, вес и стоимость.

Фильтры по периоду, диспетчеру, водителю, типу груза и региону применяются к отчёту и файлам Excel/PDF. Стоимость перевозки учитывается по фактической дате доставки.

## Тема и мобильные экраны

По умолчанию сайт следует светлой или тёмной теме устройства. Администратор может выбрать тему вручную и компактное отображение таблиц в настройках. Меню, фильтры, формы, действия и отчёты перестраиваются для узких экранов; длинные таблицы прокручиваются внутри своего блока, а столбец действий остаётся доступным.

## Настройка окружения

Для локального режима при необходимости скопируйте `.env.example` в `.env` в корне проекта. Чтобы переключить backend на облако, создайте бесплатную базу в [Turso](https://turso.tech/), затем добавьте её URL и токен в `.env`:

```env
TURSO_DATABASE_URL=libsql://имя-базы-владелец.turso.io
TURSO_AUTH_TOKEN=токен-доступа
```

Получить значения можно в панели Turso или через CLI: `turso db show --url logistics-control` и `turso db tokens create logistics-control`. Не отправляйте токен в чат и не добавляйте `.env` в git. В шаблоне backend также есть `backend/.env.example`; backend загружает сначала корневой `.env`, затем `backend/.env`. При заданных обеих переменных приложение создаёт таблицы в облачной базе при первом запуске. Если переменные пусты, используется локальный файл.

По умолчанию переключение на облако не удаляет и не меняет локальную базу. Чтобы перенести туда текущие записи, сначала настройте облачные переменные, затем выполните:

```bash
npm run db:import:cloud
```

Импорт переносит сотрудников, учётные записи, грузы, историю, планы и настройки в пустую базу; если там уже есть записи, команда остановится. Локальный файл открывается только для чтения. Если переносить старую базу не нужно, задайте `ADMIN_BOOTSTRAP_EMAIL` и `ADMIN_BOOTSTRAP_PASSWORD` в `.env` для первого запуска администратора либо запустите `npm run seed:cloud-reset` для создания демонстрационной базы. Последняя команда очищает облачную базу.

Для production-хостинга задайте эти же два секрета в настройках backend-сервиса. Само создание облачной базы не публикует сайт в интернете: для общего доступа отдельно потребуется разместить frontend и backend.

Основные параметры:

```env
PORT=4000
CORS_ORIGIN=http://localhost:5173
DB_PATH=./data/logistics.db
TURSO_DATABASE_URL=
TURSO_AUTH_TOKEN=
BUSINESS_TIMEZONE=Asia/Bishkek
```

Путь в `DB_PATH` считается от папки `backend/`; для конфигурации из корневого `.env` укажите `./data/logistics.db`.

Во время разработки frontend доступен на `http://localhost:5173`, backend — на `http://localhost:4000`. Healthcheck: `http://localhost:4000/api/health`.

## Запуск production-сборки

```bash
npm run build
npm start
```

Backend раздаёт `frontend/dist`, если `NODE_ENV=production`. Перед внешним доступом настройте HTTPS reverse proxy и задайте безопасные значения окружения. Учётные записи и роли хранятся в выбранной базе; пароли сохраняются как salted `scrypt`-хеши, а пользовательские API используют защищённую cookie-сессию и CSRF-токен.

На бесплатном плане Turso действуют квоты провайдера; проверьте [текущие условия тарифа](https://turso.tech/pricing) перед размещением production-данных.
